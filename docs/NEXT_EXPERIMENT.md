# Следующий эксперимент: компактная история вместо полной

**Статус:** план; новых запусков по этому протоколу ещё нет.

## Вопрос

Можно ли сохранить качество поиска гиперпараметров, передавая LLM-агенту краткую сводку предыдущих экспериментов вместо полной истории?

## Условия

- **Full history:** baseline и все завершённые испытания с конфигурациями, гипотезами и измеренными loss.
- **Compact history:** baseline, лучший рецепт, число испытаний, упорядоченная таблица только из `candidate_id`, четырёх параметров и `final_dev_loss` (без полных текстов гипотез, подробных конфигураций, путей, версий и API-метаданных). Это фиксированный формат, не сводка, созданная второй LLM.
- **No history:** baseline, список оставшихся кандидатов; прошлые loss скрыты.
- **Random:** контроль без API.

Для всех методов: одинаковые `train.py`, данные, пространство поиска, seed, 5 предложений, 512 шагов на попытку. Сравнить несколько новых seed, например 49–53. Не выбирать seed по результатам и не менять параметры после просмотра теста.

## Основные метрики

1. **Primary:** лучший final dev loss после пяти предложений (сравнение в пределах одного seed).
2. **Cost:** суммарные входные и выходные API-токены, отдельно число запросов.
3. **Efficiency:** достигнутый dev loss при одинаковом числе попыток и токенов обучения.
4. **Stability:** среднее, SD и парные различия по seed.

Тестовую выборку текущего проекта не использовать повторно для выбора новой политики памяти. Для итоговой оценки нужна новая заранее зафиксированная тестовая процедура или независимый набор данных.

## Критерий успеха

Compact history считается перспективным, если его средний лучший dev loss близок к full history (например, отличие не более 0,02 nats/token, как предварительно выбранный практический порог) и расход входных API-токенов существенно ниже. Порог 0,02 не является статистическим критерием эквивалентности; для такого вывода потребуется отдельный анализ неопределённости.

## Реализация

В текущем `agent_crs.py` контекст строится функцией `build_context(base, rows, mode)`. Новый режим должен формировать **строго детерминированную компактную сводку** из `rows`, не передавая полные JSON с API usage и служебными полями. Требуется добавить вариант `compact-history` в CLI и в сборку контекста, сохранив прежние режимы без изменений. Перед запуском проверить `--dry-run`, отсутствие утечки test-данных в контекст, сохранение журналов и корректное возобновление после ошибки API.

**Примечание:** изменение `agent_crs.py` поменяет SHA-256 исходника; старые эксперименты нужно хранить отдельно и не возобновлять на изменённом коде.
