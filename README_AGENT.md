# BabyLM AutoResearch: первая версия агента

Внешняя языковая модель предлагает рецепты обучения через OpenAI Responses API.
Твоя небольшая языковая модель продолжает обучаться с нуля на ноутбуке через существующий `train.py`.
Это две разные модели: исследователь и объект эксперимента.

## Установка

Положи `agent.py`, `test_agent.py` и эту инструкцию рядом с уже имеющимися
`train.py`, `runner.py` и папкой `data/processed`.
Существующие файлы менять не нужно. Новых зависимостей нет:
агент использует стандартную библиотеку Python, обучение — уже установленные PyTorch и NumPy.

Проверка без API и обучения:

```powershell
.\.venv\Scripts\python.exe -m unittest test_agent -v
.\.venv\Scripts\python.exe .\agent.py --mode agent --name agent_01 --dry-run
```

## Что происходит при запуске

1. Обучается общая базовая конфигурация: LR 0.001, weight decay 0.1, dropout 0.1, warmup 0.1.
2. Агент получает её результат, описание задачи и список допустимых рецептов.
3. Через API он выбирает рецепт, формулирует гипотезу и ожидаемый эффект.
4. Программа проверяет выбор и запускает `train.py` с соответствующим JSON-конфигом.
5. Итоговая ошибка и настройки добавляются в журнал. Агент получает обновлённую историю.
6. После пяти новых рецептов поиск заканчивается; сохраняется лучший конфиг.

Всего по умолчанию шесть обучений: baseline + пять попыток.
Каждое — 512 steps, batch 8, block 128, то есть 524288 токенов.
Пять запросов к API, максимум 2048 выходных токенов на запрос (включая reasoning).
Автоматических повторов запросов нет. При явном повторном запуске после ошибки возможен
новый оплачиваемый запрос; завершённые ответы при `--resume` используются повторно.
Входные токены и стоимость API учитываются отдельно от токенов обучения.

## Режимы

| Режим | Как выбирает рецепт | Какие результаты видит |
|---|---|---|
| `random` | Равномерно случайно, без повторений | Не использует результаты для выбора |
| `agent` | Языковая модель | Baseline и все завершённые попытки текущего поиска |
| `no-history` | Та же языковая модель | Только baseline; результаты последующих попыток скрыты |

Во всех режимах повторы рецептов запрещены. В `no-history` список доступных вариантов
исключает предыдущие выборы, поэтому модель может вывести, какие рецепты уже выбирались,
но их качество и объяснения ей не передаются. Это проверка пользы истории результатов.
Старый `journal.csv` из сравнения learning rate не импортируется: все методы начинают
с одинаковой базовой конфигурации и заново измеренного baseline.

## Область поиска

| Параметр | Допустимые значения |
|---|---|
| learning rate | 0.0005, 0.001, 0.002, 0.003 |
| weight decay | 0, 0.01, 0.1 |
| dropout | 0, 0.1, 0.2 |
| warmup fraction | 0, 0.1, 0.2 |

108 комбинаций, из них одна — baseline, остаётся 107 новых кандидатов.
Рецепт может менять несколько параметров сразу; выигрыш такой комбинации сам по себе
не доказывает вклад каждого параметра. Для этого потребуются отдельные сравнения.
Архитектура, batch, число шагов, training seed и dev-окна фиксированы.
Каждая попытка начинается с новой модели; переноса весов между попытками нет.

## Запуск случайного подбора

```powershell
.\.venv\Scripts\python.exe .\agent.py --mode random --name random_01
```

Этот режим не требует API-ключа. Не запускай несколько обучений одновременно:
они будут конкурировать за процессор.

## Подключение OpenAI

Нужен ключ OpenAI API с доступом к выбранной модели. Получить или создать ключ:
https://platform.openai.com/api-keys

Введи его локально, со скрытым вводом, в том же окне PowerShell:

```powershell
$apiSecret = Read-Host "OpenAI API key" -AsSecureString
$env:OPENAI_API_KEY = [System.Net.NetworkCredential]::new("", $apiSecret).Password
Remove-Variable apiSecret
```

Ключ не записывается в файлы проекта, команды или журнал.
Не присылай его в чат. Переменная действует в текущем процессе PowerShell и его дочерних процессах.
По умолчанию модель агента — `gpt-6-luna`; доступность зависит от API-аккаунта.
Можно передать `--model ИМЯ_МОДЕЛИ`; модель должна поддерживать Responses API,
Structured Outputs и `reasoning.effort=low`.

Сначала проведи поиск с историей:

```powershell
.\.venv\Scripts\python.exe .\agent.py --mode agent --name agent_01
```

Затем, когда первый поиск проверен, можно добавить вариант без истории:

```powershell
.\.venv\Scripts\python.exe .\agent.py --mode no-history --name nohist_01
```

Удалить ключ из текущего окружения после работы:

```powershell
Remove-Item Env:OPENAI_API_KEY
```

## Результаты и сравнение

Каждый поиск создаёт `searches/ИМЯ/`:

- `plan.json` — бюджет, конфигурация, режим, хеши кода и данных.
- `journal.csv` — одна строка на обучение, гипотеза, настройки, ошибка и время.
- `history.json` — подробная история.
- `summary.json` — baseline, лучший результат, улучшение, расход токенов API.
- `best_config.json` — настройки лучшего рецепта, совместимые с `train.py --config`.
- `trial_XXX/` — предложение, запрос/ответ API, лог, метрики и веса обучения.

Агенту передаются настройки и метрики; тексты корпуса и test.bin он не получает.
Для каждого запроса используется `store=false`, история явно передаётся из файлов текущего поиска.
Код обучения агент в этой версии не редактирует; shell-команды от модели не исполняются.

Сравнение двух или трёх методов:

```powershell
.\.venv\Scripts\python.exe .\agent.py --compare random_01 agent_01
.\.venv\Scripts\python.exe .\agent.py --compare random_01 agent_01 nohist_01
```

Сравнение проверяет одинаковые данные, код, training seed и бюджеты.
В журнале есть кривая `best_so_far_dev_loss`: по ней видно, как быстро поиск находит решения.
Выбор победителя основан на **final dev loss**, а не лучшем промежуточном checkpoint.
Baseline также может остаться победителем — положительный эффект агента не гарантирован.

## Остановка, ошибки, повторение

Завершённые поиски не перезаписываются. Для нового используй другое `--name`.
Продолжить прежний с теми же аргументами:

```powershell
.\.venv\Scripts\python.exe .\agent.py --mode agent --name agent_01 --resume
```

Завершённые обучения не повторяются. Если обучение прервалось, перед продолжением
переименуй только незавершённую папку `searches/agent_01/trial_XXX/training`, например
в `training_interrupted`. Тогда повторится обучение текущего рецепта с нуля;
его уже сохранённое предложение и ответ API сохранятся. Автопродолжения checkpoint нет.
После изменения кода, данных или параметров нужен новый `--name`.

HTTP 401 обычно означает проблему ключа, 429 — лимита или доступного API-баланса;
404 может означать отсутствие доступа к имени модели. Неверный ответ или ошибка API
останавливают поиск и не заменяются скрытым случайным подбором.
При incomplete response из-за лимита токенов создай новый поиск с, например,
`--max-output-tokens 4096`. Внутренние обучающие попытки ограничены 30.

## Что можно утверждать после первого поиска

Это пилот подбора рецептов на одном training seed и внутренних dev-окнах.
Даже если агент победил один случайный поиск, пока нельзя утверждать, что он в целом лучше.
Следующий исследовательский шаг: повторить независимые поиски с разными `--search-seed`
(это управляет только случайным подбором) и отдельно проверить найденные лучшие рецепты
на новых training seed, одинаковых для всех методов. LLM не обещает детерминизм.
Seed 43 и 44 уже использовались в предыдущем сравнении LR; для новой проверки
победителей можно заранее зафиксировать 45, 46, 47.
Официальная оценка BabyLM и отложенный test остаются для заключительного сравнения.

## Проверено при подготовке

Офлайн-тесты проверяют скрытие истории, отклонение недопустимых/повторных кандидатов,
отказов и неполных ответов API, совместимость бюджетов и обработку ключа.
Интеграционные прогоны используют реальные данные и существующий `train.py`.
Без пользовательского API-ключа ответы OpenAI в интеграционном тесте подменяются;
полноценный запрос к OpenAI нужно проверить первым запуском на своём аккаунте.
